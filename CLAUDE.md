# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Petsa de Peligro: a Java Swing 30-day student budget survival game (NetBeans/Ant project, entry point `petsa.ui.GameApp`). It is a group term project (CSS123P), so OOP concepts (inheritance, polymorphism) should stay visible in the code. There is no unit-test suite (`test/` is empty).

## Build and run

- Build check (PowerShell), using NetBeans' bundled JDK 25:
  `$env:JAVA_HOME="C:\Program Files\Apache NetBeans\jdk"; & "C:\Program Files\Apache NetBeans\extide\ant\bin\ant.bat" clean jar`
- Keep the code Java-8-compatible even though `javac.source/target` is 25 (it also compiles on JDK 1.8).
- OneDrive breaks Ant's Clean (read-only synced folders). On this PC `build.dir`/`dist.dir` are redirected to `%LOCALAPPDATA%\PetsaDePeligro2\` via the git-ignored `nbproject/private/private.properties`, so the jar is not under the project's `dist/`.
- Run a test situation (ending, Rent Day, 100% Stress, rainy day, two auto-play months): run `src/petsa/demo/ScenarioLauncher.java`. It goes through `GameApp.forTesting()`, which uses `saves_test.csv` / `leaderboard_test.csv` instead of the real data.
- Standalone Windows app: `tools/build-app.bat` (javac + jar + jpackage; also builds the WiX installer if WiX 3.14 is installed) -> `release/`. Never change the installer's `--win-upgrade-uuid`.

## Architecture

Two packages plus one demo class:

- `petsa.model`: game logic with no Swing. `GameEngine` drives the day loop over `GameState` (day, weather, apartment, pending effects) and `Player` (attributes, inventory). `Timeline` and `TimeSlot` define the day's slots. `Task` is the abstract base for `EatTask`, `HygieneTask`, `StudyTask` and `WalkTask`. `RandomEvent` is the base for the 9 phone events, scheduled by `EventScheduler` (including the rain rules). `PartTimeJob` runs shifts, `DailyLedger` handles cash and the rent bill, and `SaveManager` / `LeaderboardManager` handle CSV persistence. These classes are consolidated, with many nested classes (`ApartmentType`, `Attribute`, `DayType`, `GameSnapshot`, ...). Nested classes keep their old names, so look inside the parent file.
- `petsa.ui`: Swing screens and overlays. `GameApp` is the single frame and switches screens itself. `RoomPanel` is the main in-game view, and its overlays (Phone, Window, Shelf, Board, Notebook, RentDay, ...) pop up over it. `PixelKit` holds the shared pixel font, painting helpers, image loading, `peso()` formatting and common widgets (`WoodButton`, `PaperCard`, ...). Resources are in `src/petsa/ui/resources/`.
- `petsa.demo.ScenarioLauncher`: the only demo, replacing the old console demos.

Persistence: saves, the leaderboard and settings live in `%APPDATA%\Petsa de Peligro` via `GameApp.dataFile()`, which copies old working-directory files once. `*.csv` and `settings.properties` in the project root are git-ignored test or leftover data.

Settled design rules (do not re-litigate): 10 rainy days per month are drawn at game start (days 2-29) and saved. Academic Commission, Discount and Utang happen once a month, and the other events rotate least-used-first with no back-to-back repeats. Study keeps +5 Stress. Stress at 100% lasts until a walk or hangout. A paid laundromat adds no water. The Bed is available only after tonight's task. Closing the window mid-game asks Save & Exit / Exit / Keep playing. Phone event lines colour each effect separately (`PhoneOverlay.effectColor`).

## Branches and comments

- `main` has the commented source. `no-comments` is an orphan branch checked out as a worktree at `..\PetsaDePeligro2-NoComments`. It is generated by `tools/StripComments.java` through `tools/update-no-comments.bat` and must never be hand-edited. After committing and pushing `main`, run that script to regenerate it.
- To verify the stripping, compile both with `-g:none` and compare the `.class` hashes. They must be identical.
- `tools/StripComments.java` needs to keep working, so write comments in plain `//` and `/** */` styles.
- The old "Java Program Group 1 document.docx" is outdated. The current design doc is the Claude Doc "Petsa de Peligro - Design Document (Revised Draft)", also exported as a `.docx` in the project root (git-ignored).

## Environment notes

- Commits use the GitHub no-reply email, never the user's Gmail. `gh` is git's credential helper.
- In the PowerShell tool, refresh `$env:Path` from Machine+User for git and gh, since they were installed with winget. Long one-liners using `Remove-Item` on variable paths may be blocked by the safety filter, so use `-LiteralPath` with literal paths.
- The Claude desktop app is MSIX-packaged, so writes under `%APPDATA%` or `%LOCALAPPDATA%` may be redirected and invisible to the user's own apps. Put user-facing outputs in the project folder.
